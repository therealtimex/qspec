# qspec 1.12.0: where the data is, how we get it, and how we know

Design brief from System Design, 2026-09-06. Delivery target: a branch `qspec-1.12.0` on `/Users/realtimex/github/qspec` (GitHub `therealtimex/qspec`) from `main` at 44fdeda (v1.11.0). No forge, as for every loop since 1.7.0: delivery is the pushed branch at a named SHA; do not tag or release, System Design does that after QA.

## Context

The Q-007 committee sheet's "Still needed" list names institutions, not sources: "Provincial road asset inventories… Source: Department of Transport… Expected horizon: (not stated)." The first item has no source at all. A material entry holds `item`, `source`, `horizon`, `probability`, and the writer honoured the rule to leave a horizon empty rather than invent one. Nothing asked the writer to go and look. The research brief did: the principal can request or purchase data and the team can help collect it, by scraping if needed. Locating a source is the cheapest research in the pipeline and the one that can kill a question at selection instead of a year later. The same sheet shows two rendering defects: sentence-form labels are lowercase at the start of a sentence ("handles sensitive data. carries political risk."), and, from the last regeneration, three dossiers still fail paperforge's layout probe on wide tables.

## Decisions

- **ADR-1.12.0-1 Provenance on every material still needed.** `materials.obtainable[]` entries gain optional `access` (catalog: `open_download`, `on_request`, `purchase`, `scrape`, `partner`, `unknown`), `locator` (a URL, portal name, dataset identifier, or archive reference), `coverage` (years, units, or scope seen), and `evidence` (how the writer knows it exists: a page visited, a data dictionary, a paper that used it as `[@key]`). `materials.blocking[]` entries may be a string, as today, or an object with `item` and the same four fields; lint, renderings, and M9 accept both forms. The catalog carries a label and sentence form for each access value. Templates show the object form with a comment naming the catalog.
- **ADR-1.12.0-2 A horizon is a consequence of access, not a guess.** Two warnings, no block: `material-unlocated` when an obtainable or blocking entry has neither `locator` nor `evidence`; `horizon-without-access` when `horizon` is filled and `access` is missing or `unknown`. Core section 7's materials rows say that a horizon may be stated when the access mode is known, and that the tool still never writes one.
- **ADR-1.12.0-3 The sheet says where and how.** Each "Still needed" line renders as: item; where it is (locator); how it is obtained (access label); what it covers; how we know (evidence, with the citation marker passed through); expected horizon; likelihood. Missing parts are omitted, not rendered as "(not stated)", except the horizon, which keeps its current treatment. A `--draft` sheet lists "Source for: <item>" under "Before submission" for every unlocated material, and the sheet reports a `manual` finding `sheet-materials` naming them, in the shape of `sheet-ask`. The dossier renders the same lines.
- **ADR-1.12.0-4 Locating is part of writing; verifying is part of reviewing.** SKILL.md's workflow gains a step before routing: for every material still needed, search for the actual source with the same tools used for citations, record locator, access, coverage, and evidence, and list in the handoff what was found and what was not. The reviewer's step says: follow every locator as you follow every DOI; a locator that resolves to nothing is a finding. The scaffolded guidance block gains one sentence to the same effect; the fingerprint changes and `init --refresh` clears STALE.
- **ADR-1.12.0-5 Four rendering and wording fixes that belong with this.** (a) A sentence-form label at the start of a sentence is capitalised: "Handles sensitive data. Carries political risk." (b) The dossier's Design line uses the design's label, not the raw token, matching the threats table below it. (c) A `--draft` sheet's "Before submission" list names "Method family" when it is empty, so the social template prompts from the start, and "Threats to identification" once the family is causal, as now. (d) `bin/qspec`, an extensionless copy of the entry point with the node shebang and the executable bit, becomes the documented invocation: SKILL.md, README, the guidance block, and the `next:` hints printed by `init` and `new` drop the `node` prefix and the `.js`; `qspec.js` stays for Windows and explicit use; `init` records the invocation as it was run.
- **ADR-1.12.0-6 Dossier tables fit the reading edition.** The run timeline renders with four columns, run, command, verdict, notes; the Decision Record table with four, date, actor, act (from → to), run, with reason and dissent as lines beneath the table rather than columns. If the dossier for a real note still exceeds paperforge's narrow-layout probe after that, Dev looks for a per-type or per-document paperforge setting that scopes the layout check and uses it in the manifest template if one exists; if none exists, Dev reports the exact probe width and the widest remaining element and stops, and the acceptance below is amended by System Design. Paperforge itself is not changed.
- **ADR-1.12.0-7 Versioning and docs.** Minor release 1.12.0: optional fields, catalog entries, two warnings, one manual finding, rendering and wording. Every 1.11.0 spec, record, and Index is a valid 1.12.0 one. Bump every version string the bundle check holds and the four schema document headers; core sections 7, 8.4, 10, 14, 15; overlay templates; CHANGELOG, README, SKILL.md in the shape of the earlier entries.

## Non-goals

- No required field; that is a 2.0 change.
- No tool verification of a locator; the reviewer follows it.
- No change to paperforge.
