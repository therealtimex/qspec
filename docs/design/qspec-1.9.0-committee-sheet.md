# qspec 1.9.0: the Selection Sheet is written for a committee

Design brief from System Design, 2026-09-05. Delivery target: a branch `qspec-1.9.0` on `/Users/realtimex/github/qspec` (GitHub `therealtimex/qspec`) from `main` at 70a8bb4 (v1.8.0). No forge, as for 1.7.0 and 1.8.0: delivery is the pushed branch at a named SHA; do not tag or release, System Design does that after QA.

## Context

Five specs now render as dossiers with References sections. A dossier is the process record: fields, Decision Record, run timeline, and every attached note, for the people inside the process. A research committee is a different reader. The document it receives must carry no machine token (`empirical_causal`, `sensitive_data`, `political_risk`), no tool vocabulary (M invariants, J numbers, fingerprints, runs, versions, the word QSPEC), and no handoff or review note. QSPEC already names that document: core section 10's Selection Sheet, what a decision-maker freezes a question from "without reconstructing the claim orally". Today `lib/render.js` renders it for the tool's convenience: a `**Status:**` row, raw family and goal values, raw constraint values, `Q-005@3`. 1.9.0 makes the Selection Sheet the committee document and the Portfolio Index the round's comparison table beside it, and moves the dossier to paperforge's internal allowlist.

## Decisions

- **ADR-1.9.0-1 Labels live in the catalog.** `schema/catalogs.json` gains a human label for every value the tool can emit: each family, goal, constraint value, `access_risk` level, `hints` value, recommended action, state where a sheet may name one, and every profile field name (`treatment` reads "Intervention or exposure", `assignment_process` reads "How units come to be treated", `estimand` reads "Quantity estimated", `identifying_assumption` reads "Key assumption", `main_alternative_explanation` reads "Main alternative explanation", `precommitted_checks` reads "Pre-committed checks", `design_risk` reads "Design risk"; the same for the natural-science and engineering profiles). Labels are English; the shape allows a `vi` label beside each later. `scripts/check-judged.mjs` or a sibling check fails when any emitted value or profile field lacks a label, so a new catalog value cannot reach a document unlabelled. Labels are vocabulary for reading, not fields of a spec; the rule that the tool never writes a field is untouched.
- **ADR-1.9.0-2 The Selection Sheet is rewritten for a reader, in this order.** Head: `# Research question` then the title, then rows `**Question:** Q-005, version 3` (the paperforge pointer, worded for people; `qspec paper` and the integration doc accept both `Q-005@3` and this form), `**Selection round:** 2026-09` when an Index is given, `**Owner:**`. Sections, each a sentence or short prose, never a raw token: the claim; why it matters (`why_it_matters`, `object`, `scope` folded into prose); the design (family and goal as one labelled sentence, then the profile's required and filled optional fields under their labels, then `secondary_method` and `rescue_rule` when set); what is known and what is still open (closest work as prose per entry with `[@key]` where a key exists, so paperforge appends References); what would count as support, what would count as failure, and when the study stops (`support_would_look_like`, `failure_would_look_like`, `kill_condition`, worded as prose); materials in hand and to obtain with source and horizon, and the access risk label; constraints as labelled sentences ("Handles sensitive data. Carries political risk."); the ask; the round's recommended action as a sentence when an Index entry exists; unresolved dissent as "A reviewer dissents:" with the point verbatim, because core section 9.3 requires it on the sheet. No status, `instance_version`, fingerprint, run, note, invariant code, or `first_check` row; `first_check` belongs to the next stage, not the committee.
- **ADR-1.9.0-3 The Portfolio Index is rewritten the same way.** `# Selection round 2026-09` head with date and decision-maker; the table's columns read Rank, Question, Field, Design, Claim, Blocked, Recommended; domain, family, and action cells carry labels; "Frozen this round" lists titles with ids. Its mechanical checks are unchanged.
- **ADR-1.9.0-4 A gate on the rendered text.** `sheet` and `index` refuse to emit, with a `block` finding `committee-clean` naming the token and the line, when the rendered markdown contains any of: a snake_case identifier of two or more segments that matches a catalog value or profile field name, `M` or `J` followed by one or two digits as a word, the words `fingerprint`, `instance_version`, `Decision Record`, `QSPEC`, `run`/`runs` as a word in a heading or a head row, or the literal `@` between an id and a number. The denylist is one exported array in `lib/render.js` and is tested against a rendering that deliberately violates each rule. Prose a person typed is checked too; a writer who types `empirical_causal` into `scope` is told which line to reword.
- **ADR-1.9.0-5 State gate kept; a preview for owners.** `sheet` still renders only for `selectable`, `deferred`, and `frozen`. `--draft` renders for any state with a head row `**Draft:** unsigned, not for submission` and a closing section "Before submission" listing the empty fields by label; `render` never emits drafts into `sheets/` unless `--draft` is passed, and then writes them under `drafts/`. `committee-clean` applies in draft mode too.
- **ADR-1.9.0-6 Manifest roles change.** In `templates/documents.qspec.toml`, dossiers move to the `[internal]` allowlist with `reason = "process records: runs, review notes, decisions"` so paperforge can never publish them; `qspec-sheet` and `qspec-index` remain document types with `publish = false`, the strict `todo` lint applies to them, and the sheet type carries `bibliography` and `citation_style`. `render --manifest` prints missing entries as before; `docs/paperforge-integration.md` updates the section and says in one sentence which document goes to a committee and which stays inside.
- **ADR-1.9.0-7 The suite's marker grep and the dossier.** The `todo` marker grep keeps covering sheets, index, and requests. The dossier is unchanged in content and remains the process record; the only change is where the manifest puts it.
- **ADR-1.9.0-8 Versioning and docs.** Minor release 1.9.0, additive: no instance field, M invariant, record, or Index shape changes; `committee-clean` is a `block` on a rendering, not on a spec, which section 14 permits in a minor release as 1.3.0's `index-stale` was. Bump every version string the bundle check holds and the four schema document headers; core section 10 describes the sheet's new order and the gate, section 11 the Index's labels, section 8.4 lists `committee-clean`, section 14 gains the bullet, section 15 notes `--draft`. CHANGELOG, README, SKILL.md follow the 1.5.0 to 1.8.0 entries; SKILL.md's routing row for "Give a person a document" now says: the sheet for a committee, the dossier for the people inside the process.

## Acceptance criteria

1. `npm test` passes, with new checks: every catalog value and profile field the renderer can emit has a label (the check fails on a fixture catalog missing one); the sheet for `examples/ss-causal-procurement-cutoff.yaml` contains no token from the denylist and does contain the labels for its family, goal, constraints, and profile fields; a fixture spec carrying `empirical_causal` inside `scope` is refused with `committee-clean` naming the line; `sheet --draft` renders a draft with the draft row and the "Before submission" list, and `render` without `--draft` writes no draft; the Index for `examples/index-round-2026-09.yaml` carries labelled cells and no denylisted token; the marker grep still passes.
2. `node scripts/plugin.mjs --check` passes.
3. Proof, reported in the Dev handoff with the run name: in a temp project built from `examples/` with `examples/references.bib`, `render --out documents` then `paperforge all --draft --config documents/documents.toml` builds the sheet for Q-101 to html and pdf with a References section and no denylisted token in the html text, and the dossier is not among the published document types.
4. Nothing under `policyforge/vietnam/vn-procurement` is modified.

## Non-goals

- No third document type; sheet, Index, and internal dossier cover the committee, the round, and the process.
- No Vietnamese labels yet; the shape allows them.
- No change to what the dossier contains.
- No change to paperforge.
