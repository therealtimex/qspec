# qspec 1.7.0: dossier, render, and documents a person can read

Design brief from System Design, 2026-09-04. Delivery target: a branch `qspec-1.7.0` on `/Users/realtimex/github/qspec` (GitHub `therealtimex/qspec`) from `main` at a965602. This loop declares no forge: the repository is on GitHub, not the app's GitLab; delivery is the pushed branch at a named SHA, reviewed and QA'd from there. Do not tag or release; System Design does that after QA.

## Context

Three specs now sit in `policyforge/vietnam/vn-procurement` with 26 runs and 7 attached notes. Everything is YAML, JSON, and markdown. The people who must sign, freeze, and fund a question read documents. Paperforge renders and gates documents from markdown and refuses YAML on principle. The 2026-09-02 decision to keep the two tools separate with a file contract stands; what is missing is two renderings on the qspec side and a documented manifest on the paperforge side.

## Decisions

- **ADR-1.7.0-1 The seam does not move.** qspec renders markdown in Paperforge head format; paperforge renders html, pdf, docx. No YAML parser enters paperforge, no document renderer enters qspec, no npm dependency enters the bundle.
- **ADR-1.7.0-2 `qspec dossier <spec> [--out file] [--label text]`.** One markdown document per spec, for a person: head rows (`**Question:** Q-id@version`, status, domain and profile, owner, reviewers), then the spec's fields as prose sections in core order (claim, question type, increment with `closest_work` as a table, materials, success and failure, constraints, ask, hints, the profile's fields from the catalog field list, handoff), then the Decision Record as a table (date, actor, role, from, to, reason, run, dissent), then the run timeline as a table (name, label, command, verdict, blocks, notes), then every attached note in chronological order under a heading naming kind, actor, role, run, and time, with the note text copied whole. The tool never rewrites, trims, or summarises a note. Renders for any state including `draft`; refuses only an unparseable spec. Adds `{#claim-q-<id> gist="<one_sentence>"}` on the claim paragraph only when the spec is `frozen` and the sentence is gist-representable, reusing the check `paper` already has. Records a run with command `dossier` and the markdown under `rendered/`.
- **ADR-1.7.0-3 `qspec render --out <dir> [--specs dir] [--index round.yaml] [--label text]`.** Writes, under `<dir>`: `dossiers/<id>.md` for every spec; `sheets/<id>.md` for every spec in a sheet-able state, using the one Index found in the specs directory or the one named by `--index`, and refusing with a clear message when there are several and none is named; `index/<round>.md` for every Index; `requests/<id>.md` for every frozen spec. A file that cannot render is listed with its reason and the others still render; exit 1 only when a spec that should have rendered blocked. Overwrites only its own outputs and never touches other files under `<dir>`. Records one run with command `render` whose entries name every file written, with the rendered markdown kept.
- **ADR-1.7.0-4 The manifest is documented and templated, not written by qspec.** Paperforge owns its manifest schema. qspec ships `templates/documents.qspec.toml`, a complete `documents.toml` for a `documents/` paperforge project sitting inside a QSPEC project: `[types.qspec-sheet]` and `[types.qspec-index]` with `layout = "brief"`, `[types.qspec-dossier]` with `extends = "report"`, one `[[collection.document]]` per rendered file, every document `publish = false`. `docs/paperforge-integration.md` gains a section "Documents from a QSPEC project" that says: scaffold with `paperforge init --into documents --publications brief --no-git`, replace the manifest with the template, `qspec render --out documents`, then `paperforge all --draft --config documents/documents.toml`. When `render` is given `--manifest <documents.toml>` it prints, to stdout, the `[[collection.document]]` entries that manifest lacks for files it just wrote; it never edits the manifest.
- **ADR-1.7.0-5 A dossier is a process record and builds in draft mode.** Paperforge's `todo` rule blocks TODO, TBD, FIXME, XXX, and PLACEHOLDER anywhere in a document; attached notes will contain them. Sheets, Indexes, and requests must stay clean and the suite's marker grep keeps covering them; dossiers are excluded from that grep and are built with `paperforge all --draft`, which reports every finding and refuses nothing but cannot publish. Say this in the docs and in the guidance.
- **ADR-1.7.0-6 Guidance and fingerprint.** The scaffolded `AGENTS.md` block gains `dossier` and `render` lines and one sentence: for a person, `qspec render --out documents/` then `paperforge all --draft --config documents/documents.toml`. `COMMANDS` in `lib/scaffold.js` gains `dossier` and `render`; the guidance fingerprint changes and `init --refresh` clears the resulting STALE, as with 1.5.0 and 1.6.0.
- **ADR-1.7.0-7 Run labels collide across loops; scope, do not rename.** `reviewer-round-1` now names one Q-002 run and one Q-003 run, so `runs.load` refuses the short name. Add `--spec <id or path>` to `runs`, `runs show`, and `runs --diff`: when given, name resolution considers only runs whose `files` include that spec, and listing filters to them. Labels are not auto-prefixed; the writer chooses them.
- **ADR-1.7.0-8 Versioning.** Minor release 1.7.0, additive. No instance field, M invariant, record shape, or Index shape changes. Bump every version string the bundle check holds to one value: `package.json`, `plugin/realtimex.plugin.json`, `plugin/skills/qspec/SKILL.md`, `schema/catalogs.json`, and the four schema document headers. CORE section 15 lists `dossier` and `render`; section 14 gains the 1.7.0 bullet; CHANGELOG, README, and SKILL.md follow the 1.5.0 and 1.6.0 entries in shape and tone. SKILL.md's routing table gains a row "Give a person a document to read or sign from".

## Acceptance criteria

1. `npm test` passes, with new checks: a dossier for a draft spec contains a line from an attached note verbatim; a dossier for the frozen example carries the claim label with the frozen sentence as gist and a dossier for a draft does not; `render` on a project holding one draft, one selectable, and one frozen spec writes exactly the expected files, skips the sheet for the draft with a reason, and records one `render` run whose entries name every file; `runs show <short label> --spec <id>` resolves where the bare label is ambiguous; the marker grep still passes over sheets, index, and requests, and dossiers are excluded from it.
2. `node scripts/plugin.mjs --check` passes: the bundle is in sync, one version everywhere, every SKILL.md link resolves, `templates/documents.qspec.toml` ships under `tool/templates/`.
3. Proof on the real project, reported in the Dev handoff with run names: in `/Users/realtimex/github/policyforge/vietnam/vn-procurement`, scaffold `documents/` with paperforge, install the template manifest, `qspec render --out documents`, then `paperforge all --draft --config documents/documents.toml` produces html, pdf, and docx for the Q-003 dossier under `documents/`. Do not commit anything under `vn-procurement` to policyforge; it is untracked by decision until a person signs a spec.
4. No note text is altered by rendering: the dossier's copy of every note is byte-identical to `notes/<file>` in its run, apart from the heading the dossier adds above it.

## Non-goals

- No change to paperforge. The `qspec` lint pack on the paperforge side waits for a frozen spec.
- No automatic editing of a paperforge manifest by qspec.
- No mirror of RealTimeX loop handoffs into runs; that is a loops-plugin change and has its own follow-up.
- No new act, no new M invariant, no new record field.
